# 中国大陆 `research_only` 私测版合规与数据治理边界

> 研究基准日：2026-08-01  
> 适用场景：AlphaFlow 面向受邀的专业 A 股个人投资者，使用 TuShare、Minishare 与 LLM 提供专业市场基线、个性化研究信息、站内研究收件箱以及飞书等外部提醒。  
> 文档性质：产品与工程侧的法规研究及风险分层，不构成法律意见，不替代中国证券监督管理委员会派出机构、属地网信部门或专业律师的正式认定。

## 一、结论

`research_only` 应当被理解为一组可验证的产品和服务端限制，而不是免责声明：系统可以呈现可追溯的数据事实、现实中值得研究的变化、证据、影响路径、分歧、不确定性和待验证条件；不得结合用户资产、持仓、成本、风险承受能力生成买卖动作、仓位、入场/目标/止损价格或执行计划，也不得让 Agent、定时任务、外部提醒等旁路重新产生这些内容。

这能显著降低被认定为个性化证券投资顾问服务的风险，但不能当然排除证券投资咨询、金融信息服务报备、互联网新闻信息服务许可、算法备案或生成式人工智能监管。AlphaFlow 的核心对象是专业投资者，目的又是辅助金融研究与决策，至少高度贴近《金融信息服务管理规定》及境内金融信息服务报备通知所描述的金融信息服务；基于用户关注项和行为排序、主动推送研究事件也属于算法推荐。上线前必须由证券及网信合规律师结合实际输出样例、注册范围、收费/商业获益模式、数据合同和运营主体逐项确认。

私测版的保守上线门槛应为：受邀实名用户、服务端强制 `research_only`、不采集组合金融信息、仅使用经书面核验可展示/派生/再分发的数据、站内完整留痕、外部渠道只发最小提醒副本、LLM 只引用输入证据、生成内容显著标识、人工抽检与违法有害内容处置、个性化可关闭和清除、完整的用户协议/隐私政策/风险揭示/数据来源/投诉入口；在金融信息服务、新闻转载、生成式 AI/算法手续获得明确结论前，不面向不特定公众开放。

## 二、判断口径

本文把结论分成三类：

- **确定义务**：可以直接从现行官方文件推出，满足适用条件即应执行。
- **需确认事项**：是否落入某项许可、备案或特定业务定义，取决于产品事实，必须由律师或主管机关确认。
- **保守产品建议**：法条未直接要求这一具体 UI/架构，但它能控制前述风险并留下可审计证据。

产品名称、邀请制、免费、免责声明、由 LLM 而非人工生成，都不能单独改变业务实质。私测并不当然等于“不向公众提供”，也不当然免除个人信息、内容、数据安全及知识产权义务。

## 三、证券投资咨询边界

### 3.1 确定义务

1. 中国证监会发布的《证券投资顾问业务暂行规定》将证券投资顾问业务置于取得证券投资咨询业务资格的证券公司、证券投资咨询机构框架内。证监会的投资者答复进一步明确，只有经许可并取得证券投资咨询业务资格的证券公司和证券投资咨询机构才可以向投资者销售“荐股软件”，且“荐股软件”是提供证券投资咨询服务的一种方式。自动化或软件化不会把投资建议变成普通数据服务。[中国证监会第27号公告及附件](http://www.csrc.gov.cn/csrc/c101838/c1022038/content.shtml)；[中国证监会投资者答复](http://www.csrc.gov.cn/csrc/c106299/c1600683/content.shtml)
2. 《金融信息服务管理规定》第四条明确：金融信息服务提供者从事互联网新闻信息服务、法定特许或应备案的金融业务，应取得相应资质；金融信息服务身份不能替代证券业务许可。[国家网信办：《金融信息服务管理规定》](https://www.cac.gov.cn/2018-12/26/c_1123908386.htm)
3. 因此，未取得证券投资咨询业务资格时，服务端不得面向用户输出具体证券的个性化买卖、持有、加减仓、仓位、价位和执行顺序，也不得通过 Agent、简报、私信或飞书绕开该限制。页面免责声明只能作为风险揭示，不能使实质上的投资建议合法化。

### 3.2 `research_only` 可保留和必须排除的能力

可保留：

- 数据观测：指标、口径、时点、来源、数据质量与历史对比；
- 研究事件：现实变化、为何值得研究、事实与推断分层、关联公司/行业/主题、证据、分歧与不确定性；
- 非个人组合导向的研究假设、验证条件、反证、风险因素和情景分析；
- 用户明确选择公司、行业、主题后对信息进行相关性排序，并解释“为什么推给我”；
- 高层级市场状态和事件日历，但普通波动不得自动包装成研究事件。

必须由服务端排除：

- `BUY/SELL/HOLD/ENTER/ADD/TRIM/EXIT/PROBE` 等交易动作，包括对已有持仓给出的“继续持有”；
- 建议仓位、资金分配、风险预算、入场区间、追价上限、目标价、止损/失效价、分批执行与订单计划；
- 读取现金、总资产、持仓数量、成本、建仓日、个人风险承受能力后生成证券结论；
- “最适合买入”“确定性机会”“胜率/收益保证”等诱导性、承诺性表达；
- 由外部提醒直接给出可执行结论，或通过链接参数/API 暴露被 UI 隐藏的交易字段。

### 3.3 需律师或主管机关确认

以下边界不能仅凭 `research_only` 名称决定：

- 对用户自选股持续生成公司级方向性观点、目标价值区间或强弱排序，是否仍构成“针对具体证券的投资建议”；
- 以订阅费、会员费、数据费、广告、开户链接、流量分成等方式获益时，是否进入证券投资咨询经营边界；
- LLM 四项分发评分以及紧急提醒是否在具体样例中实质形成买卖时机信号；
- 面向“专业投资者”的邀请制范围是否足以构成特定对象金融信息服务，以及适用哪一证券监管口径。

在取得书面结论前，MVP 不输出目标估值/目标价格、方向评级、证券排名或时机信号，不收费，不接券商开户导流，不连接证券账户，不下单，也不公开宣传历史收益、命中率或“跑赢 Wind/iFinD”。

## 四、生成式人工智能与算法边界

### 4.1 生成式人工智能

《生成式人工智能服务管理暂行办法》适用于利用生成式 AI 向境内公众提供生成内容的服务；企业等研发、应用但未向境内公众提供服务的，不适用该办法。提供者包括通过 API 提供服务的组织或个人。办法要求合法来源的数据/基础模型、知识产权和个人信息合规、内容准确可靠、服务协议、输入与使用记录保护、违法内容处置、投诉举报；具有舆论属性或社会动员能力的服务还涉及安全评估和算法备案，其他行政许可仍应依法取得。[国家网信办等：《生成式人工智能服务管理暂行办法》](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)

**确定义务（落入公众服务范围时）**：

- 公开适用人群、场合、用途；与注册用户签订服务协议；不收集非必要个人信息；保护输入及使用记录；
- 建立违法内容停止生成/传输/消除、记录保存、报告与用户违规处置流程；提供投诉举报入口；
- 提高准确性和可靠性，不能让模型自行补充输入中不存在的事实；训练或微调数据必须来源合法并尊重知识产权、个人信息权益。

**需确认事项**：邀请制私测是否已经是“向境内公众提供”；AlphaFlow 是上游已备案模型的普通应用方、生成式 AI 服务提供者，还是二者兼具；是否具有舆论属性或社会动员能力而需安全评估、算法备案。调用已备案的第三方模型 API 不当然转移 AlphaFlow 对产品输出和用户数据的责任。

**保守产品建议**：即使私测阶段最终不适用该暂行办法，也按其服务规范设计；只选择已完成境内所需手续、合同允许金融场景且明确数据保留/训练政策的模型供应商；禁止供应商用用户输入、研究偏好、证据包训练；高重要性或低置信度内容进入人工抽检队列。

### 4.2 算法推荐和自动化决策

《互联网信息服务算法推荐管理规定》所称算法推荐包括生成合成、个性化推送、排序精选等技术。提供者应告知算法推荐情况、适当公示基本原理/目的/主要机制，提供不针对个人特征的选项或便捷关闭功能，允许选择或删除用户标签；具有舆论属性或社会动员能力的，应在提供服务起十个工作日内履行算法备案。[国家网信办等：《互联网信息服务算法推荐管理规定》](https://www.cac.gov.cn/2022-01/04/c_1642894606364259.htm)

《个人信息保护法》第二十四条同时要求：利用个人信息自动化决策应透明、公平、公正；自动化信息推送或商业营销应提供非个性化选项或便捷拒绝方式；对个人权益有重大影响的自动决定，个人有权要求说明并拒绝完全自动化决定。[全国人大：《中华人民共和国个人信息保护法》](http://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html)

对 AlphaFlow 的可操作边界：

> 当前私测 MVP 进一步采用数据最小化方案：只处理用户明确设置的研究关注，不采集查看、搜索、展开等行为用于个性化，也不生成行为标签或兴趣线索。下列行为标签控制是未来若启用行为个性化时的上线前要求，不是当前 MVP 功能清单。

- 专业市场基线必须在零偏好、关闭个性化后仍完整可用；
- 用户可查看、修改、删除显式关注与行为标签，可关闭行为信号、个性化排序、紧急提醒和外部副本；
- 每条个性化内容保留触发原因、所用标签/信号、规则和版本；不得静默扩大研究范围；
- LLM 只返回重要性、置信度、相关性、信息增量的分数、分项依据、引用证据和不确定性；代码校验引用、执行阈值、去重、冷却、频控和最终分发，模型不能直接发送；
- 在主管机关确认前按“可能具有舆论属性”准备算法自评估、备案材料和应急能力，未得明确结论不开放公众服务。

### 4.3 AI 生成内容标识

《互联网信息服务深度合成管理规定》要求对生成/编辑内容添加不影响使用的技术标识、按规定保存日志；智能写作等可能导致公众混淆的服务应作显著标识。[国家网信办等：《互联网信息服务深度合成管理规定》](https://www.cac.gov.cn/2022-12/11/c_1672221949354811.htm)

2025 年 9 月 1 日施行的《人工智能生成合成内容标识办法》进一步规定文本等生成内容的显式标识、文件元数据隐式标识、传播平台核验/提示、服务协议说明和不得恶意删除标识；用户申请无显式标识内容时还涉及协议义务与不少于六个月日志留存。[国家网信办等：《人工智能生成合成内容标识办法》](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)

MVP 应在每个 LLM 研究事件解释、评分依据和简报上显著显示“AI 生成/辅助生成”、生成时间、模型/提示版本、证据版本与不确定性；复制、下载、导出时保留标识，若形成文件则写入合规的元数据隐式标识。飞书副本也必须带 AI 标识，不得因为消息短而移除。

## 五、数据来源、新闻和再分发边界

### 5.1 金融信息服务

《金融信息服务管理规定》把“向从事金融分析、交易、决策等活动的用户提供可能影响金融市场的信息和/或金融数据”定义为金融信息服务，要求建立内容审核、数据保存、信息安全、个人信息与知识产权保护制度；在显著位置准确注明来源并确保可追溯；配备专业人员审核，禁止虚假金融信息、歪曲政策、虚构市场事件等；发现禁止内容时应立即停止传播、处置、留存记录并报告。[国家网信办：《金融信息服务管理规定》](https://www.cac.gov.cn/2018-12/26/c_1123908386.htm)

境内金融信息服务报备通知描述的典型对象正是境内机构通过互联网/专用终端向金融机构或专业投资者等特定对象提供信息和数据以辅助金融决策；通知同时说报备采取“自愿申报”，报备只是对行为的确认，不替代其他业务资质。面向社会公众提供金融资讯则不属于该通知所称报备范围，而应遵守互联网新闻信息服务等规定。[国家网信办：境内金融信息服务报备通知](https://www.cac.gov.cn/2022-01/28/c_1644970476680085.htm)

**需确认事项**：AlphaFlow 受邀专业投资者私测高度符合报备特征，应在上线前向注册地省级网信部门书面咨询是否提交报备、何时提交以及产品应如何明示报备状态。不能把“自愿申报”解释为相关管理规范不适用，也不能把报备宣传为证券业务许可。

### 5.2 TuShare、Minishare 与新闻

积分或 API 可访问权限不等于对外展示、缓存、派生、商用或再分发许可。当前仓库材料只证明接口字段和调用方式，不包含足以证明下列权利的有效合同：

- 将 TuShare 行情、资金、财务、公告、研报等字段向 AlphaFlow 用户展示或批量导出；
- 将 Minishare 聚合自新浪财经、华尔街见闻、同花顺、财联社、东方财富等来源的全文缓存、摘要、改写后站内或飞书再传播；
- 将数据送入第三方 LLM、用于训练/微调、长期保存或生成商业派生产品。

因此这是**上线阻断项**：逐数据集建立权利台账并取得供应商书面条款，至少记录数据所有者/供应商、来源、许可主体、用途、用户范围、展示字段、缓存期限、派生权、LLM 处理、外部投递、导出、审计与终止删除。TuShare 15,000 积分只能写作接口调用条件，不能写作授权结论；Minishare 也必须获得自身及底层新闻内容的转授权范围证明。

《互联网新闻信息服务管理规定》把有关政治、经济等社会公共事务的报道、评论定义为新闻信息；通过网站、应用、公众账号、即时通信工具等向社会公众提供采编发布、转载或传播平台服务须取得许可。获许可的转载者也应从国家规定范围单位转载，注明来源、作者、原标题、编辑，并遵守著作权。[国家网信办：《互联网新闻信息服务管理规定》](https://www.cac.gov.cn/2017-05/02/c_1120902760.htm)

**需确认事项**：私测收件箱和飞书向受邀用户提供 Minishare 新闻全文、摘要、LLM 改写或评论，是否构成面向社会公众的转载/传播或其他互联网新闻信息服务；LLM 的“研究事件”何时从事实抽取跨越为新闻采编/评论。应将页面样例、用户边界、消息渠道及数据合同交由网信律师和属地网信部门确认。

在确认前采用以下保守规则：

- 默认只保存必要的事实字段、来源名称、原始发布时间、抓取时间、原文 URL、权利状态和内容哈希；不对外展示或推送第三方新闻全文；
- 研究事件用 AlphaFlow 自有结构表达，关键事实逐条引用输入证据并链接原文；不得把改写当成规避著作权或新闻许可的方法；
- 公告、政策、交易所文件等优先链接官方原始来源；来源冲突时不得自动发布紧急提醒；
- 飞书只发送站内消息 ID、标题、为什么提醒、AI 标识、数据截至时间和站内链接；不发送全文证据包、新闻正文、用户研究偏好或敏感信息；
- 供应商撤回、纠错、授权终止或证据降级时，保留修订记录并停止后续分发，不静默覆盖历史。

### 5.3 数据安全

《网络数据安全管理条例》要求网络数据处理者建立制度并采取加密、备份、访问控制、安全认证等措施；向其他处理者提供或委托处理个人信息、重要数据时，应以合同约定目的、方式、范围和保护义务并监督，相关记录至少保存三年；还要求按规定识别、申报重要数据。[国务院：《网络数据安全管理条例》](https://www.gov.cn/zhengce/zhengceku/202409/content_6977767.htm)

AlphaFlow 应为原始数据、数据观测、研究事件、LLM 输入/输出、收件箱和投递日志分别分类分级；凭证与业务数据隔离，最小权限访问，加密传输/存储，建立删除、供应商终止、数据泄露和错误推送处置流程。2026 年《金融信息服务数据分类分级指南》已由国家网信办等六部门印发，应作为金融信息数据盘点和重要数据识别的最新行业依据。[六部门：《金融信息服务数据分类分级指南》通知](https://www.cac.gov.cn/2026-06/13/c_1782919789934988.htm)

## 六、个人信息边界

### 6.1 信息分类

- 账号标识、联系方式、自选股、收藏公司/行业/主题、搜索、查看、展开、忽略、反馈、收件箱状态、设备/IP 与消息投递记录，只要能关联自然人，均是个人信息。
- 持仓、成本、现金、总资产和证券账户信息至少属于高风险金融相关个人信息；《个人信息保护法》明确把金融账户列为敏感个人信息。是否所有组合字段在具体场景均属法定敏感个人信息，需律师确认，但 MVP 没有处理必要性，故不采集最稳妥。
- 用户输入和研究笔记可能含身份、内幕/未公开信息或第三方个人信息，不能默认送给 LLM。

### 6.2 确定义务

《个人信息保护法》要求目的明确合理、直接相关、最小范围、公开透明和最短保存；处理前显著告知处理者、目的、方式、种类、期限和权利路径；向其他处理者提供个人信息通常需告知接收方并取得单独同意；敏感个人信息需特定目的、充分必要、严格保护、单独同意及额外告知；个人有查阅、复制、更正、删除等权利。敏感信息、自动化决策、委托/提供以及跨境提供等活动应事前开展个人信息保护影响评估，记录至少保存三年。[全国人大：《中华人民共和国个人信息保护法》](http://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html)

### 6.3 MVP 控制

- 不采集总资产、现金、持仓、成本、风险偏好、计划持有期；不从旧模型或测试表读取这些数据参与研究与分发；
- MVP 只处理显式研究关注，不采集或派生行为辅助信号；未来若引入，必须与显式关注分开开关、分开告知，且只能改变排序、不屏蔽专业市场基线、不用于广告或其他目的；
- 提供标签查看/修改/删除、非个性化基线、关闭个性化、关闭外部提醒、查询/复制/更正/删除/注销入口；
- 对个性化推送、LLM 处理、向模型供应商/飞书的委托或提供、潜在跨境分别做 PIPIA 和数据流图；合同限定用途、留存、再委托、训练与删除；
- 若模型端点、日志、客服或飞书导致个人信息出境，必须在启用前完成适用的跨境路径、单独同意与告知；在确认前禁止向境外端点发送可识别用户的输入、偏好或消息；
- 研究收件箱是权威记录，严格按用户隔离；飞书 target 只保存不含 webhook 密钥的引用，秘密放入专用凭证存储并限制访问；投递内容实行字段白名单和防泄漏扫描。

## 七、内容治理边界

《网络信息内容生态治理规定》要求内容平台履行主体责任，建立用户注册、信息发布审核、实时巡查、应急处置等制度；不得传播违法信息，应防范不良信息；发现后应处置、保存记录并按要求报告；个性化算法应有人工干预和用户自主选择机制，并设置投诉入口。[国家网信办：《网络信息内容生态治理规定》](https://www.cac.gov.cn/2019-12/20/c_1578375159509309.htm)

叠加金融信息和生成式 AI 规则，MVP 至少需要：

1. **发布前**：输入来源准入、恶意内容清洗；LLM 结构化输出；引用存在性校验；事实/推断/不确定性分层；交易语义、虚假金融信息、歪曲政策、违法有害内容拦截；紧急提醒高风险样本人工复核。
2. **发布中**：展示来源、原文 URL、发布时间、抓取/生成/更新时间、数据口径、AI 标识、置信度与修订状态；未知或证据不足时不得写成事实。
3. **发布后**：用户反馈、投诉举报、纠错/撤回、原消息修订链、来源撤回同步；违法内容停止生成/传输/消除，保存记录并按适用规则报告。
4. **运营纪律**：不得购买或生产“必涨”“内幕”“黑马”等内容；不得让互动量、付费或用户依赖驱动夸张推送；不得以频繁紧急提醒诱导交易。

分发门槛中的四项分数均由 LLM 生成并不违反“代码最终决策”原则，但评分不是合规判断。服务端必须验证四项完整、分项依据只引用输入证据、引用 ID 存在、阈值/去重/冷却/频控通过；任何一项解析失败、证据冲突、来源权利未知或不确定性越界时降级为站内候选或不发布。

## 八、`research_only` 私测版服务端控制基线

| 控制面 | 必须实现的控制 | 验收证据 |
|---|---|---|
| 模式与权限 | 服务端单一 `research_only` 策略；所有 API、工作流、Agent Skill、定时任务、导出与投递共同调用；默认拒绝未知能力 | 策略版本、路由/工作流覆盖清单、拒绝日志 |
| 用户范围 | 邀请制、实名账号、禁止分享账号；未完成许可/报备判断前不开放匿名访问和公众注册 | 邀请与账号审计记录 |
| 输入最小化 | 组合/资产/成本/风险偏好字段拒收、拒读、拒传 LLM；用户自由文本做敏感/第三方信息提示和扫描 | 契约测试、字段审计、数据流图 |
| 数据准入 | 外部数据先过 provider/dataset 权利台账和规范化；权利未知不得进入展示、LLM 或分发 | 数据权利台账、供应商合同指针 |
| LLM 证据约束 | 输入证据具有不可变 ID；输出只可引用这些 ID；分数+依据+证据+不确定性模式校验；事实不得越界 | 原始输入/输出、模型与 prompt 版本、解析结果 |
| 并发与限流 | 四项评分可并行/批量调用，但设置全局、模型、用户、工作流并发上限、超时、重试预算和熔断；失败不得放宽质量门槛 | 排队/耗时/429/重试/失败指标 |
| 交易输出阻断 | 结构化契约中无交易动作/仓位/价格字段；枚举和语义双层拦截；流式输出先缓冲校验再发送 | 负向测试、拦截审计样本 |
| 分发 | LLM 不得调用发送能力；代码执行四门槛、去重、增量、冷却、频控；紧急提醒支持人工复核开关 | 决策轨迹、规则版本、人工复核记录 |
| 收件箱 | 先写入站内不可变版本，再异步投递副本；未读/稍后/归档不改变原内容；纠错以修订追加 | 消息版本链、投递幂等键 |
| 外部提醒 | 用户主动绑定和可关闭；字段白名单，仅标题/原因/AI 标识/时点/站内链接；不含全文、证据包、偏好、资产数据；发送前防泄漏扫描 | 投递 payload 审计、同意与退订记录 |
| AI 标识 | 页面、复制、导出、飞书均显式标识；文件含隐式元数据；不得由用户静默去除 | UI/导出契约测试、文件元数据测试 |
| 个性化 | 完整非个性化基线；MVP 只使用可关闭、可查看、可修改和可删除的显式研究关注；保留按需触发原因解释 | 用户设置与研究偏好快照 |
| 内容治理 | 发布前审核、违法有害内容处置、投诉举报、纠错撤回、监管报告预案；高风险样本人工抽检 | SOP、处置台账、演练记录 |
| 个人信息 | 隐私告知、PIPIA、最短留存、用户权利、访问控制、加密、事件响应；第三方模型与飞书合同治理 | PIPIA、留存矩阵、权限审计 |
| 可追溯性 | 每条研究对象记录数据截至时间、来源、权利状态、模型/提示/规则版本、证据、生成与修订链 | 可回放审计包 |

性能优化不能牺牲边界：LLM 可并发但每个调用都必须经过统一调度和审计；stale-while-revalidate 可以返回旧快照，但必须显著显示数据时间、完整性和修订状态；降级时宁可少发或只显示数据观测，不得跳过来源、引用或交易语义校验。

## 九、上线前阻断清单

以下任一项未完成，`research_only` 私测不应开始真实用户运营：

1. 证券律师已基于真实样例书面确认公司级研究输出、四项评分和提醒不越过当前无牌照边界，或产品已按意见再收缩；
2. 属地网信部门/律师已确认金融信息服务报备路径、互联网新闻信息服务边界、生成式 AI/算法的备案和安全评估要求；
3. TuShare、Minishare 及底层新闻逐数据集完成书面授权核验，明确展示、缓存、派生、LLM、外发和导出范围；
4. 上游模型和飞书的数据处理、日志、训练、再委托、存储地、删除与安全义务完成合同和技术核验；
5. 服务端 `research_only` 策略已覆盖所有同步、异步和外部投递路径，并通过负向测试；
6. 用户协议、隐私政策、独立风险揭示、AI 与算法说明、数据来源、投诉举报和个人权利入口已上线；
7. PIPIA、数据分类分级、留存删除矩阵、内容处置和安全事件预案已完成并演练；
8. 真实投递采用站内先写、外部最小副本，所有消息可追溯、可修订、可退订。

## 十、与当前仓库事实的关系

本节只描述工程事实，不把它们写成法律结论：

- `docs/regulation.md` 已识别组合信息、交易动作、执行计划、交易类 Agent Skill、流式输出和收益展示风险；本研究认可其收敛方向，并补充官方法源和许可/报备边界。
- `CONTEXT.md` 已定义研究模式、专业市场基线、数据观测、研究事件、四项分发评估、三级分发与研究收件箱；这些定义可作为产品契约，但仍需本文的服务端限制。
- `python_services/app/providers/minishare/news.py` 已并发抓取并规范化 Minishare 新闻，`web/prisma/schema.prisma` 与证据上下文保存来源名称、URL、发布时间等字段；这是可追溯性的基础，不代表已取得再分发权。
- `web/server/infrastructure/intelligence/deepseek-client.ts` 调用第三方 LLM API；仓库未显示对输入个人信息、供应商训练/留存、生成标识和全链路输出合规校验的完整控制。
- `web/tooling/scheduler-delivery.ts` 当前可把完整 `body/summary` 发到飞书；未来研究收件箱落地时必须改为本文规定的最小提醒副本，且站内记录先于外发。
- `agent_runtime/src/pi-adapter.ts` 已有“不得输出买卖建议”等提示，但提示词不能替代 Skill 白名单、结构化契约、服务端校验和流式缓冲。
