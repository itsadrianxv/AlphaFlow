# 首页数据清单与数据获取结算拓扑

Status: accepted

首页数据及其来源证据、修订和两层首页数据清单以 PostgreSQL 追加式记录作为唯一权威源。专业市场基线清单面向所有用户共享；个性化首页清单引用一个基线清单并只追加用户专属清单项。每个清单项独立运行首页数据清单项获取尝试，采用至少一次执行、数据库幂等和 fencing 结算。Python Provider 只负责外部来源访问与规范化，`data-acquisition-worker` 负责租约、重试和通过 PostgreSQL repository 原子写入来源断言/修订、结算清单项并执行门控；`homepage-worker` 只读取已固定的清单和修订集合生成不可变首页快照。

## Considered Options

- 让 Python Provider 直接写库：拒绝，因为会把来源适配和研究持久化耦合，并难以与 C++ Worker 结算保持原子。
- 一个任务覆盖整份首页数据清单：拒绝，因为单个数据集失败会重复执行已成功的数据集，并扩大租约与重试范围。
- 以事件存储或对象存储作为第二权威源：拒绝，MVP 通过 PostgreSQL 中的不可变原始记录、修订和清单集合完成重放。

## Consequences

结果重建重放从已固定清单和修订集合生成，不访问 Provider；数据重新获取创建新的获取尝试，只有规范化选值变化或上游更正才创建新修订。个性化清单按需创建，个性化数据迟到时可继续读取旧个性化快照或专业市场基线快照，不阻塞全局首页。
