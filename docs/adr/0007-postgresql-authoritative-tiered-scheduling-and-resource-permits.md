# PostgreSQL 权威的分级调度与全局资源许可

AlphaFlow 后台任务采用交互级、时段关键级和后台级三个调度等级，并在每个执行资源池内由 PostgreSQL 以确定性加权方式原子领取；任务生命周期、全局资源许可、自适应并发和熔断状态均以 PostgreSQL 为权威源，Redis 仍只负责至少一次唤醒。公开供应商限额按账户全局执行，未公开限额通过共享的自适应并发控制，所有分页、批处理和嵌套调用都必须取得对应资源许可；已运行任务不因更高等级任务到达而抢占，只在过时、取消或租约失效时协作式终止。

## Consequences

调度 module 必须把加权公平、目标完成时间、背压、许可租约和 fencing 隐藏在小型领取/许可 interface 后面，各 Worker 和业务 workflow 不得自行维护权威限流状态或以无界 `Promise.all` 绕过资源池。具体权重、积压上限、重试预算、熔断参数和分数据源/交易阶段时效目标属于可校准运行配置，由对应决策票记录并以私测指标验证。
